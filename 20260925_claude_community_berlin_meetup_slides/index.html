Turns & stops

A turn is a duration.
A stop is an event.

EventExit 2
StopPrevents Claude from stopping, continues the conversation
SubagentStopPrevents the subagent from stopping

The Stop event’s superpower is preventing itself.

The innermost ring

Editor Loop

Seconds-fast feedback: tools from your existing stack, wired into agent lifecycle hooks.

edit → format → lint →
compile → test → fix
↺ repeat until pass

Format before lint: formatting needs no code understanding, and avoids re-triggering style rules.

Why the Stop hook?

Fires once per turn — checks the finished state. Per-tool-call hooks would run the full check on every edit.

Why no MCP?

Claude natively reads stdout and exit codes. MCP adds a moving part.

Every tool used is like a CLI. That enables feedback with minimal delay.
The idea

One verify.sh — sensors you already have

CLI tools you would run without AI as well. Same script for humans, agents, pre-commit and CI.

My proposal — every team decides what is best for them:

Blueprint · brownfield_word_freq

Brownfield: verify only what changed

Full verify on every Stop is too expensive. Gate on real changes, escalate by size.

Conclusion

Code is cheap.
Verified software isn’t.

  1. Reuse the CLI tools you already trust as sensors
  2. One verify.sh for humans, agents, pre-commit, CI
  3. Stop hook = hard gate with a bounded retry budget
  4. Greenfield: run everything + cache
    Brownfield: change-scoped, escalate by size

Monday morning

  2. Identify your loops
  3. Start with the innermost one: the editor loop
  4. Use something like verify.sh
